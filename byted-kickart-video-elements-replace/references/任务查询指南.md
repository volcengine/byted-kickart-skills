# 任务进度查询工具使用指南

## 一、概述

本指南使用 `@volcengine/kickart-open-mcp@1.1.x` 的 `query_task_v2` 查询视频元素替换任务。任务完成后默认自动发布成片到 KickArt，并返回本地响应 JSON 路径。

## 二、前置依赖

1. 已确认 CLI 可用且 OAuth 登录态有效。
2. 当前会话存在有效 `task_id`，或用户明确提供要查询的 `task_id`。

## 三、CLI 参数说明

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--task-id` | string | - | 提交成功时返回的任务 ID |
| `--source` | `"ad_variations" \| "kickart_ai_material"` | - | 视频元素替换使用 `ad_variations` |
| `--auto-publish` | boolean | `true` | 完成后是否自动发布结果视频；固定传 `true` |

视频元素替换任务固定传入 `--source ad_variations`，不得由用户改写。参数行为不确定时先执行 `query_task_v2 --help`。

## 四、调用示例

```bash
npm exec -y --registry=https://registry.npmjs.org --package @volcengine/kickart-open-mcp@1.1.x -- kickart-open-cli query_task_v2 \
  --task-id 7619174133103902774 \
  --source ad_variations \
  --auto-publish true
```

## 五、返回结果说明

- `status = "running"`：展示 `task_id`、`progress` 和 `message`；后续查询由用户主动触发，不得自动轮询。
- `status = "completed"`：提取 `result_url`、`payload`、`usage`、`response_file_path` 和可选的 `published_media`。
- `status = "failed"`：反馈 `message`，并保留 `raw` 和 `response_file_path` 便于排查。
- 命令非零退出时读取并脱敏 stderr，不把日志文本当作业务 JSON。

## 六、Agent 执行流程

1. 命中“查询进度”“查看结果”“生成怎么样了”“好了吗”时，优先读取本指南，禁止重新提交任务。
2. 先从当前会话上下文获取最近一次视频元素替换任务的 `task_id`；没有有效 ID 时告知用户未查询到相关提交任务。
3. 按固定版本 CLI 执行查询命令，解析真实 stdout JSON 和本地响应文件。
4. 查询失败时依次检查 Node.js/npm、网络、OAuth 登录态、套餐和接口权限；不得直接请求 OpenAPI 或使用内部轮询命令。
